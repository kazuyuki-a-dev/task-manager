## 1. 目的

> 約20人の製造業の職場で、「だれが何をやっているか」と「締め切り」がひと目で分かり、遅れる前に気づけるようにする。

今は製造の指示と生産の予定を Excel で管理している。このアプリは、その Excel の代わりになることを目指す。

## 2. 使う人と使う環境

| 項目 | 内容 |
|---|---|
| 使う人 | 約20人（管理者と作業者） |
| 開く道具 | 現場の共用タブレット・共用PC（1台を何人かで使う） |
| 動かす場所 | 社内のネットワークの中だけ。インターネットには出さない（D-005） |
| 知らせ方 | アプリを開いたときに画面に表示する。メールやチャットには送らない（D-006） |

## 3. 役割

| 役割 | できること | 操作する人の分け方 |
|---|---|---|
| 作業者（だれでも） | 全体を見る。どの指示の内容（製品・数量・材料集結日・納期）・状態も直す。指示に担当を足す・外す。会社カレンダーを見る（休む人の名前だけ） | 名前は選ばない。だれが操作したかは分からなくてよい（D-023） |
| 管理者 | 作業者ができることすべて。指示を作る・消す、社員を登録する、製品を登録する、会社カレンダーに休みを登録する | パスワードを入れる（D-004） |

## 4. 機能の優先度

| 分け方 | 機能 |
|---|---|
| **主役** | ① 進み具合のボード ② 期限の見える化 |
| **必須** | 製造指示の登録と編集、状態を変える、名前を選ぶ操作と管理者のパスワード、社員の登録、変更の記録、毎日のバックアップ、完了の履歴、担当を足す、製品の一覧と検索、会社カレンダー |
| **補助** | コメント、絞り込み（担当別・期限別）、CSV の取りこみと書き出し |
| **後回し** | メールやチャットへの知らせ、在庫・部品の管理、ガントチャート、工程ごとの進み具合、スマホ向けの画面、実際にかかった日数（会社の稼働日で数える）（D-021） |

新しく思いついた機能は、まず「後回し」に入れる。主役と必須がそろうまで手をつけない。

## 5. 完成の境界

次の2つがそろったら、この版を完成とする。

1. 主役と必須の要件が、要件の対応表ですべて「完了」になっている
2. 職場で Excel の代わりに **1週間** 使い、主役の2つが使えると確かめられた

## 7. 運用の要件

社内のネットワークで動かすため、次のことを公開前に決める（未決 Q-03〜Q-05）。

| 項目 | 決めること |
|---|---|
| 動かす機械 | どの機械で動かすか、だれが面倒を見るか |
| バックアップと戻し方 | どこに保存するか、何日分残すか、どこまで失ってよいか、何時間で戻すか |
| 止まったとき | だれが気づき、だれに連絡し、どう戻すか |
| 社員の出入り | 入社・退職のとき、だれがいつ登録を変えるか |

## 8. 守るもの

- 製造の指示（品名・数量・納期など）は社外に出さない情報として扱う
- 社員の休みが有給か欠勤かは、その人の休みの記録なので、管理者だけが見られるようにする。作業者の画面には、休む人の名前だけを出す（D-020）
- このリポジトリは公開しているので、**会社の名前・本物の品名・お客さんの名前は Git に入れない**。試すためのデータはダミーにし、ダミーだと分かる印を付ける
