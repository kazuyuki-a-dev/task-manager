## この手順書の使い方

- 上から順に、**1つずつ**やってください。とばさないでください。
- 「**打つもの**」は、ターミナルに打つ文字です。1行ずつコピーして貼りつけ、**Enter キー**を押します。
- 「**こう出たら成功**」と同じような文字が出たら、次のステップに進みます。
- 「**こう出たら**」の文字が出たら、そこに書いてあることをやります。それでもうまくいかないときは、「D. うまくいかないとき」を見ます。
- ⚠ の印があるステップは、**まちがえると元に戻せません**。やる前に、書いてあることを確かめてください。
- `task-manager-20261120-123000.sql.gz` のような名前は**例**です。自分のファイルの名前に変えて打ちます。

### ことばの意味

| ことば | 意味 |
|---|---|
| ターミナル | 文字を打って、パソコンに指示する画面 |
| バックアップ | データベース（アプリのデータが入っているところ）の中身を、1つのファイルに書き出したもの。名前は `task-manager-年月日-時分秒.sql.gz` |
| 戻す（復元） | バックアップのファイルから、データベースの中身を元に戻すこと |
| Sail（セイル） | このアプリを Docker（アプリを箱に入れて動かす道具）で動かすための道具。コマンドは `./vendor/bin/sail` で始まる |

## ステップ 0. はじめに（毎回やる）

### 0-1　ターミナルを開く

どこで：Windows のスタートメニュー

やること：スタートメニューを開き、「**Ubuntu**」と打って、出てきた「Ubuntu」を押します。黒い画面（ターミナル）が開きます。

こう出たら成功：
```
orange@パソコンの名前:~$
```
（`orange` のところは、自分の名前です）

> **貼りつけ方**：ターミナルでは、Ctrl+V ではなく **Ctrl+Shift+V** で貼りつけます（マウスの右クリックでも貼りつけられます）。

### 0-2　アプリのフォルダに移る

どこで：Ubuntu のターミナル

打つもの：
```
cd ~/task-manager
```

こう出たら成功：
```
orange@パソコンの名前:~/task-manager$
```
（うしろに `~/task-manager` が付けば、移れています）

こう出たら：
```
cd: /home/orange/task-manager: No such file or directory
```
→ アプリがこの PC にありません。PC を新しくしたときは「C. PC がこわれた・なくなった」に進みます。

### 0-3　アプリが動いているか見る

どこで：Ubuntu のターミナル（0-2 のあと）

打つもの：
```
./vendor/bin/sail ps
```

こう出たら成功（2行出て、どちらも `Up` と出ている）：
```
NAME                          IMAGE          COMMAND             SERVICE        CREATED       STATUS                 PORTS
task-manager-laravel.test-1   sail-8.5/app   "start-container"   laravel.test   6 hours ago   Up 5 hours             0.0.0.0:80->80/tcp, ...
task-manager-mysql-1          mysql:8.4      "docker-entrypoi…"  mysql          6 hours ago   Up 5 hours (healthy)   0.0.0.0:3306->3306/tcp, ...
```

こう出たら（`NAME` の行しか出ない）：
```
NAME      IMAGE     COMMAND   SERVICE   CREATED   STATUS    PORTS
```
→ アプリが止まっています。次の 0-4 で起動します。

### 0-4　アプリを起動する（止まっていたときだけ）

どこで：Ubuntu のターミナル

打つもの：
```
./vendor/bin/sail up -d
```

こう出たら成功（最後に `Started` と出る）：
```
 Container task-manager-laravel.test-1  Started
 Container task-manager-scheduler-1  Started
```
→ 30秒ほど待ってから、もう一度 0-3 をやり、`Up` と出ることを確かめます。

> `scheduler`（スケジューラー）は、バックアップを自動でとる係です。アプリ・データベースと一緒に、3つ動いていれば大丈夫です。

## A. ふだんのバックアップ

### A-1　毎日のバックアップがとれているか見る（ときどき）

アプリは、**毎日 12:30 に、自動でバックアップをとります**（書き出しているあいだも、ボードは止まらずに使えます）。とれているかを、ときどき見ます。

#### かんたんな見方：管理者の画面のいちばん上を見る

どこで：ブラウザ（ボードの右上の「管理者」から入る）

こう出たら成功（緑の枠）：
```
最後のバックアップ：11/20(金) 12:30（3時間前）
task-manager-20261120-123000.sql.gz
```

こう出たら（赤の枠）：
```
⚠ 1日以上、バックアップがとれていません
最後のバックアップ：11/17(火) 12:30（3日前）
```
または
```
⚠ まだバックアップがありません
```
→ 下の A-2 で手でとってから、担当に知らせます。うまくいかない理由は、アプリのフォルダの `storage/logs/laravel.log` に書かれています。

> **12:30 に PC が止まっていても大丈夫です。** スケジューラーが5分ごとに「とれているか」を見ていて、とれていなければ、アプリを起動してから（0-4）**5分以内に**とります。たとえば、きのうの 12:30 に PC を止めていたら、今朝アプリを起動してから5分以内に、きのうの分をとります。

> 最後のバックアップから **25時間** たつと赤になります。アプリを起動してから5分ほどで、とれていなかった分がとれて緑になります。5分たっても赤のままなら、0-3 で3つ（`laravel.test`・`mysql`・`scheduler`）が `Up` になっているかを見て、A-2 で手でとります。

#### ターミナルで見る方法

どこで：Ubuntu のターミナル（ステップ 0 のあと）

打つもの：
```
ls -l storage/app/private/backups/
```

こう出たら成功（きのうや今日の日付のファイルがある）：
```
-rw-r--r-- 1 orange orange 6678 Nov 20 12:30 task-manager-20261120-123000.sql.gz
```
→ ファイルの名前の `20261120` が日付（2026年11月20日）、`123000` が時刻（12時30分00秒）です。

こう出たら（ファイルがない、または何日も前のものしかない）：
→ 自動のバックアップが動いていません。A-2 で手でとってから、管理者の担当に知らせます。自動で動かす設定は `docs/operations.md` の「3. 機械が決まったらやること」です。

### A-2　いま手でバックアップをとる（大きな変更の前など）

どこで：Ubuntu のターミナル（ステップ 0 のあと）

打つもの：
```
./vendor/bin/sail artisan backup:database
```

こう出たら成功：
```
バックアップをとりました：/var/www/html/storage/app/private/backups/task-manager-20261120-164057.sql.gz
```
→ いちばんうしろの `task-manager-20261120-164057.sql.gz` が、いまとったバックアップのファイルの名前です。

こう出たら：
```
Sail is not running.
```
→ アプリが止まっています。0-4 で起動してから、もう一度打ちます。

### A-3　バックアップを PC の外にコピーする（週に1回くらい）

**PC がこわれると、PC の中のバックアップも一緒に消えます。** なので、外付けディスクや社内の共有フォルダにもコピーしておきます。

> 保存先が決まったら、アプリが毎日そこへ直接書くように設定できます（`docs/operations.md` の「3. 機械が決まったらやること」）。そうなれば、このステップは毎回やらなくてよくなります。

どこで：Ubuntu のターミナル（ステップ 0 のあと）

打つもの（バックアップのフォルダを、Windows のエクスプローラーで開く）：
```
explorer.exe storage/app/private/backups
```

こう出たら成功：Windows のエクスプローラー（ファイルを見る画面）が開き、`task-manager-…sql.gz` のファイルが並んでいます。

やること：いちばん新しいファイル（名前の日付がいちばん新しいもの）を、外付けディスクや共有フォルダに**コピー**します（ドラッグするか、右クリック →「コピー」→ コピー先で「貼り付け」）。

### A-4　一緒に保管しておくもの（はじめに1回）

PC がこわれたときに戻すには、バックアップのファイルのほかに、**アプリの設定のファイル（`.env`）の中身**もいります。

どこで：Ubuntu のターミナル（ステップ 0 のあと）

打つもの（設定のファイルを、メモ帳で開く）：
```
notepad.exe .env
```

やること：開いた中身を、決めた場所に保管します（紙に書いて鍵のかかる引き出しにしまう、など）。

⚠ **`.env` には、データベースのパスワードなどが入っています。** GitHub やチャット、メールには、ぜったいに出さないでください。

## B. まちがえてデータを消した（PC は無事なとき）

### B-1　いつのバックアップに戻すかを決める

どこで：Ubuntu のターミナル（ステップ 0 のあと）

打つもの：
```
ls -l storage/app/private/backups/
```

やること：まちがえて消す**前**の日時のファイルを選びます。名前をメモしておきます（例：`task-manager-20261120-123000.sql.gz`）。

⚠ **戻すと、そのバックアップのあとに入れた変更は、すべて消えます。** たとえば、12:30 のバックアップに戻すと、その日の 12:30 より後に入れた指示や状態の変更は消えます。

### B-2　念のため、いまの形もバックアップしておく

A-2 と同じです。

打つもの：
```
./vendor/bin/sail artisan backup:database
```

→ 戻したあとで「やっぱり戻す前のほうがよかった」となったときに、こちらに戻せます。

### B-3　⚠ バックアップから戻す

どこで：Ubuntu のターミナル（ステップ 0 のあと）

やる前に確かめること：B-1 で選んだファイルの名前が合っているか。

打つもの（`task-manager-20261120-123000.sql.gz` のところを、B-1 で選んだ名前に変える）：
```
./vendor/bin/sail artisan backup:restore task-manager-20261120-123000.sql.gz
```

こう出たら：
```
 /var/www/html/storage/app/private/backups/task-manager-20261120-123000.sql.gz から戻します。今のデータは消えます。よいですか？ (yes/no) [no]:
 >
```
→ 名前が合っていれば、`yes` と打って Enter を押します。やめるときは、そのまま Enter を押します（「戻すのをやめました」と出ます）。

こう出たら成功：
```
戻しました：/var/www/html/storage/app/private/backups/task-manager-20261120-123000.sql.gz
```
（手元で試したときは、2〜3秒で終わりました）

こう出たら：
```
バックアップのファイルが見つかりません：task-manager-20261120-123000.sql.gz
```
→ 名前がちがいます。B-1 でもう一度名前を見て、打ちなおします。

### B-4　ボードで確かめる

どこで：ブラウザ（Chrome や Edge）

やること：`http://localhost` を開き、Ctrl+Shift+R を押して読みなおします。消してしまった指示が、もどっているかを見ます。

### B-5　使う人に知らせる

「○時○分のバックアップに戻しました。○時○分より後に入れた変更は消えたので、もう一度入れてください」と知らせます。

## C. PC がこわれた・なくなった（新しい PC でゼロから戻す）

**コードは GitHub にあるので、新しい PC に持ってこられます。データは、A-3 でコピーしておいたバックアップのファイルにしかありません。**

用意するもの：
- 新しい PC（Windows）
- A-3 でコピーしておいた、バックアップのファイル（いちばん新しいもの）
- A-4 で保管しておいた、`.env` の中身

### C-1　使う人に知らせる

「アプリが止まっています。戻るまで、紙で記録してください」など、決めたやり方で知らせます。

### C-2　新しい PC に道具を入れる（はじめの1回だけ）

次の3つを入れます。くわしい入れ方は、それぞれの公式のページのとおりです。
1. **WSL2 と Ubuntu**：Windows の中で Ubuntu（Linux）を動かす道具。管理者として開いた PowerShell で `wsl --install` と打ち、PC を再起動する
2. **Docker Desktop**：アプリを動かす道具。入れたあと、設定の「Resources → WSL integration」で Ubuntu をオンにする
3. **PHP と Composer**：README の「動かし方」に書いてある道具（Ubuntu のターミナルで入れる）

確かめ方：ステップ 0-1 で Ubuntu のターミナルを開き、次を打つ。
```
docker --version
git --version
composer --version
```
3つとも、`Docker version 28.…` のように版の番号が出れば成功です。

### C-3　GitHub からアプリを持ってくる

どこで：Ubuntu のターミナル

打つもの（1行ずつ）：
```
cd ~
git clone https://github.com/kazuyuki-a-dev/task-manager.git
cd task-manager
```

こう出たら成功：
```
Cloning into 'task-manager'...
```
のあと、`orange@パソコンの名前:~/task-manager$` になります。

### C-4　設定のファイル（.env）を作る

どこで：Ubuntu のターミナル（C-3 のあと）

打つもの：
```
cp .env.example .env
notepad.exe .env
```

やること：メモ帳が開くので、A-4 で保管しておいた中身と見比べて、**データベースのパスワードなど、ちがうところ**を書きなおして保存します。

> `APP_KEY=` のところは、空のままでかまいません。次の C-5 で新しく作ります（作りなおしても、管理者のパスワードはそのまま使えます）。

### C-5　アプリを起動する

どこで：Ubuntu のターミナル（C-4 のあと）

打つもの（1行ずつ。1つ終わって、また打てるようになってから次を打つ）：
```
composer install
./vendor/bin/sail up -d
```

こう出たら成功：
```
 Container task-manager-mysql-1  Started
 Container task-manager-laravel.test-1  Started
```
→ **1分ほど待ちます**（データベースの準備に時間がかかるため）。

続けて打つもの（1行ずつ）：
```
./vendor/bin/sail artisan key:generate
./vendor/bin/sail npm install
./vendor/bin/sail npm run build
```

こう出たら成功：
```
 INFO  Application key set successfully.
```
```
found 0 vulnerabilities
```
```
✓ built in 590ms
```

⚠ **`./vendor/bin/sail artisan migrate --seed` は打たないでください。** README には書いてありますが、それは開発用のダミーデータを入れるためのものです。戻す前にダミーデータが入ってしまいます。

> この時点でボード（`http://localhost`）を開くと、まだデータがないので、エラーの画面（500）になります。C-7 で戻すと開けるようになります。

### C-6　バックアップのファイルを置く

新しく持ってきたアプリには、バックアップを置くフォルダが**まだありません**。作ってから置きます。

どこで：Ubuntu のターミナル（C-5 のあと）

打つもの（1行ずつ）：
```
mkdir -p storage/app/private/backups
explorer.exe storage/app/private/backups
```

やること：エクスプローラーで空のフォルダが開くので、A-3 でコピーしておいたバックアップのファイルを、ここに**コピー**します。

確かめ方：
```
ls -l storage/app/private/backups/
```
こう出たら成功：
```
-rw-r--r-- 1 orange orange 6678 Nov 20 16:41 task-manager-20261120-164057.sql.gz
```

### C-7　⚠ バックアップから戻す

どこで：Ubuntu のターミナル（C-6 のあと）

やる前に確かめること：C-6 で置いたファイルの名前。

打つもの（`task-manager-20261120-164057.sql.gz` のところを、置いたファイルの名前に変える）：
```
./vendor/bin/sail artisan backup:restore task-manager-20261120-164057.sql.gz
```

こう出たら：
```
 …task-manager-20261120-164057.sql.gz から戻します。今のデータは消えます。よいですか？ (yes/no) [no]:
 >
```
→ `yes` と打って Enter を押します（新しい PC はまだ空なので、消えて困るデータはありません）。

こう出たら成功：
```
戻しました：/var/www/html/storage/app/private/backups/task-manager-20261120-164057.sql.gz
```

### C-8　アプリの新しい変更を足す

バックアップをとったあとに、アプリのほうが新しくなっていることがあります。その分を足します。

どこで：Ubuntu のターミナル（C-7 のあと）

打つもの：
```
./vendor/bin/sail artisan migrate --force
```

こう出たら成功（どちらか）：
```
 INFO  Nothing to migrate.
```
（足すものがなかった）
```
 INFO  Running migrations.
 2026_12_01_000000_… .. DONE
```
（足すものがあって、足した）

### C-9　確かめる

1. ブラウザで `http://localhost` を開き、Ctrl+Shift+R で読みなおす。ボードに指示が出ていれば成功
2. 右上の「完了の履歴」「カレンダー」も開いてみる
3. 右上の「管理者」から、**前と同じ名前とパスワード**で入れるか試す（入れれば成功）

### C-10　毎日のバックアップを設定しなおす

新しい PC でも、毎日自動でバックアップをとるように設定します。やり方は `docs/operations.md` の「3. 機械が決まったらやること」です。

### C-11　使う人に知らせて、記録する

1. 「戻りました。○月○日○時のバックアップに戻したので、そのあとに入れた変更はもう一度入れてください」と知らせる
2. 下の「E. 試した記録」の表に、1行書き足す（実際に戻したときも書く）

## D. うまくいかないとき

| 出たもの・ようす | わけ | やること |
|---|---|---|
| `Sail is not running.` | アプリが止まっている | ステップ 0-4 で起動する |
| `バックアップのファイルが見つかりません` | ファイルの名前がちがう、または置く場所がちがう | `ls -l storage/app/private/backups/` で名前を見て、打ちなおす。C のときは C-6 をやりなおす |
| `戻すのに失敗しました：…` のあとに、データベースにつながらないという意味の英語が出る | アプリを起動したばかりで、データベースがまだ準備中 | 1分待ってから、もう一度打つ。続くときは 0-3 で `mysql-1` が `Up … (healthy)` になっているか見る |
| ボードを開くと、エラーの画面（500）になる | まだ戻していない（C-7 の前） | C-7 をやる |
| ボードの見た目が古い、または真っ白 | 画面の組み立てをしていない、またはブラウザが古い画面を覚えている | `./vendor/bin/sail npm run build` を打ってから、ブラウザで Ctrl+Shift+R |
| `cd: …task-manager: No such file or directory` | アプリがこの PC にない | C-3 から始める |
| 管理者で入れない | 名前かパスワードがちがう。または、1分のあいだに5回まちがえた | 1分待ってから、もう一度ゆっくり打つ |
