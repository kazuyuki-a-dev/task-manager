## 2. 毎日のバックアップ（R-09）

| 項目 | 内容 |
|---|---|
| 担当 | なし（本番は行わない・D-058） |
| 基準 | 毎日1回、データベースの全部をバックアップする。決めた日数より古いものは消す |
| 期限 | 毎日 12:30（`.env` の `BACKUP_TIME` で変えられる）。夜中は PC が止まっているため昼にする（D-045）。書き出しているあいだもボードは止まらないので、使っている時間でもよい。12:30 に PC が止まっていたら、アプリを起動してから5分以内にとる（D-047） |
| 保存先 | はじめは `storage/app/private/backups`（アプリと同じ機械の中）。**機械がこわれると一緒に消えるので、本番では別の場所（外付けディスクや社内の共有フォルダ）にする**（Q-04） |
| 残す日数 | 30日（`.env` の `BACKUP_KEEP_DAYS` で変えられる） |
| 確かめ方 | 管理者の画面のいちばん上に、最後のバックアップの日時が出る。25時間（`.env` の `BACKUP_STALE_HOURS`）以上とれていなければ赤になる。失敗した理由は `storage/logs/laravel.log`（D-046） |

### しくみ

- `php artisan backup:database` が、データベースを書き出して（`mysqldump`）、gzip で小さくして保存する
  - ファイル名：`task-manager-年月日-時分秒.sql.gz`（例：`task-manager-20261120-123000.sql.gz`）
  - 書き出しているあいだも、ボードは止めずに使える（`--single-transaction`）
  - 保存したあと、決めた日数より古いバックアップを消す。この名前の形でないファイルはさわらない
  - 失敗したら、こわれたファイルは残さず、古いバックアップも消さず、ログ（`storage/logs`）に残す
- 動かすのは、Laravel のスケジューラー（`routes/console.php`）。**5分ごとに `backup:database --if-due` を動かす**。これは「いちばん近い、すぎた 12:30 より後のバックアップがあるか」を見て、なければとる。なので、ふだんは 12:30 にとれ、12:30 に PC が止まっていたときはアプリを起動してから5分以内にとる（D-047）
- スケジューラーは、`compose.yaml` の `scheduler` の箱（`php artisan schedule:work` を動かしつづける）が動かす。`./vendor/bin/sail up -d` で、アプリ・データベースと一緒に動き出す。PC を立ち上げたときに自動で動き出す設定は、今回は入れていない（手でアプリを起動する。手順書の 0-4）

### 手で1回とるとき

```sh
./vendor/bin/sail artisan backup:database
```

## 3. （参考）本番の機械で動かすときにやること

本番は行わない（D-058）ので、この節は参考として残す。

| 順 | やること | 確かめ方 |
|---|---|---|
| 1 | `.env` に保存先と残す日数を書く（例：`BACKUP_PATH=/mnt/backup/task-manager`、`BACKUP_KEEP_DAYS=30`） | `php artisan backup:database` を手で1回動かし、保存先にファイルができる |
| 2 | Docker（Sail）のまま動かすときは、`scheduler` の箱が動いていればよい。Docker を使わないときは、毎分スケジューラーを動かす設定を1つ足す（下の例） | `php artisan schedule:list` で `*/5 * * * *  php artisan backup:database --if-due` が出る。`sail ps` で `scheduler` が `Up` |
| 3 | 次の日、保存先に新しいバックアップができているか見る | ファイルの名前の日時が、その日の 12:30 ごろ |
| 4 | 下の 4. の手順で、本番の機械でも戻す試しを1回やる | 戻す試しの記録（5.）に1行足す |

Docker を使わないときに、毎分スケジューラーを動かす設定の例（Docker のままなら、`scheduler` の箱がするので、いらない）：

- Linux（cron）：`* * * * * cd /アプリの場所 && php artisan schedule:run >> /dev/null 2>&1`
- Windows：タスクスケジューラで、1分ごとに `php artisan schedule:run` を動かすタスクを作る

## 4. バックアップから戻す（戻し方）

> **ターミナルに何を打つかまで1つずつ書いた、くわしい手順は [バックアップと復元の手順書](backup-and-recovery.md) にあります。** PC がこわれた・なくなったときに、新しい PC でゼロから戻す手順もそちらです。ここは、そのあらましです。

| 項目 | 内容 |
|---|---|
| 担当 | なし（本番は行わない・D-058） |
| 基準 | データがこわれた・まちがえて大事なデータを消した、とき |
| 期限 | 目標時間は決めない（D-058）。手元で試したときは、戻すのに3秒（指示81件） |

**戻すと、今のデータはすべて消えて、バックアップをとったときの形になる。** バックアップをとってから戻すまでのあいだに入れた変更も消える。

1. いつのバックアップに戻すかを決める（保存先のファイルの名前の日時を見る）
2. **念のため、今の形もバックアップしておく**：`./vendor/bin/sail artisan backup:database`
3. 戻す：`./vendor/bin/sail artisan backup:restore task-manager-20261120-123000.sql.gz`
   - 「今のデータは消えます。よいですか？」と聞かれるので、`yes` と答える
4. ボードを開いて、指示が出ているかを見る
5. 使う人に、戻した日時と、消えた変更があることを知らせる
